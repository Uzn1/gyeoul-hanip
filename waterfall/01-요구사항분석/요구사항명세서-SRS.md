## 1. 문서 개요

소비자가 서울에서 원하는 겨울간식 판매처를 찾고 방문을 결정할 수 있도록, 탐색·상세·제보·후기·운영에 필요한 관찰 가능한 동작을 정의한다. 기획과 개발은 범위 및 정책의 근거를, QA는 조건과 기대 결과를 참조한다.

| 구분 | 범위와 출처 |
| --- | --- |
| MVP | 서울 공개 지도·목록, 위치 거리순·자치구·간식 검색, 상세, 쓰기 권한, 제보와 운영, 리뷰·별점, 초기 출처, 방문 확인. SPD MVP-001~007 |
| 후속 검토 | 실시간 재고·예약, 결제·배달·대기열, 서울 외 지역, 사업주 전용 대시보드, 외부 리뷰·별점 이전. SPD EX-001~004 |
| 정책 근거 | [서비스기획서](../00-기획/서비스기획서.md) · [비즈니스정책서](../00-기획/비즈니스정책서.md) · [AGENT.md](../AGENT.md) |
| 화면 근거 | [DESIGN.md](https://github.com/Uzn1/gyeoul-hanip/blob/main/DESIGN.md)의 지도·목록, 상세·제보 진입, 모바일 배치. 서울 자치구와 리뷰 내용은 Phase 0 문서를 따른다. |
| 추적 문서 | [유스케이스 명세서](유스케이스명세서.md) · [요구사항 추적 매트릭스](요구사항추적매트릭스-RTM.md) |

**P1**은 Phase 0의 필수 제안, **P2**는 권장 제안이다. **방향 합의**는 사용자가 선택한 제품 방향이며 상세 정책은 검토해야 한다. **검토안**은 Phase 0 초안을 수용 기준으로 구체화한 상태다. **조건부**는 관련 결정이 확정되어야 완료를 판정할 수 있다. 세 상태 모두 G1 승인과 테스트 통과를 의미하지 않는다.

## 2. 전체 시스템 설명

| 액터 | 역할 |
| --- | --- |
| 소비자 | 로그인을 하지 않아도 서울의 판매처를 탐색하고 상세와 공개 후기를 읽는다. |
| 로그인 기여자 | 새 판매처, 기존 정보 정정, 방문 결과와 신고를 제출하고 자기 후기를 관리한다. |
| 사업주 제보자 | 공통 제보 흐름으로 판매처·메뉴·영업 정보를 제출한다. 소유 확인과 추가 권한은 DEC-002에서 결정한다. |
| 운영자 | 초기 카탈로그 출처를 검토하고, 신고·중복·공개 상태를 관리하며 검증 대상 집계를 확인한다. |
| 외부 시스템 | 브라우저는 위치 권한과 좌표를 제공한다. 인증 서비스는 작성자의 세션을 제공한다. 장소 원본은 외부 지도 링크로 연결된다. |

기본 환경은 모바일·데스크톱 웹이다. 현재 배포가 제공하는 망원동 시범 기능과 서울 확대 요구를 구분한다. 선택할 지도·인증·데이터 공급자와 확정된 구현 상태는 DEC-002·005·006과 후속 설계에서 기록한다.

## 5. 외부 인터페이스 요구사항

| UI-02 | 판매처 상세, 주소·핀, 메뉴·영업시간·이용 방식, 출처, 후기/별점, 방문 이력과 제보 진입 | FR-004, FR-012, FR-016 |

브라우저 위치 사용은 사용자 동의를 받는다. 지도 제공자와 인증 제공자, 주소·장소 출처 연결은 설계 단계에서 데이터 계약으로 정리한다. 공개 읽기, 인증 쓰기, 운영 쓰기는 권한이 다르며 API 이름과 와이어 형식은 [API 설계서](../02-시스템설계/API설계서.md)에서 다룬다.

## 6. 데이터 요구사항

| 엔티티 | 구분과 관계 |
| --- | --- |
| 판매처 | 판매처 ID, 이름, 타입 또는 분류, 서울 자치구, 공개 좌표, 주소 또는 찾는 법, 메뉴, 영업시간, 이용 방식, 확인·공개 상태를 가진다. 선택값은 미등록과 실제 값을 구분한다. |
| 출처 | 판매처에 연결된 네이버 지도·카카오맵·제보·사업주 등 근거와 확인 일시를 추적한다. 출처별 조사 수와 실물 판매처 수는 서로 다른 집계다. |
| 계정 | 로그인 기여자 소유권 및 운영 권한을 판정할 식별자와 역할을 유지한다. 확인된 사업주 표시와 검증 방법은 조건부다. |
| 제보·방문 | 대상 판매처, 기록 유형과 결과, 제출자와 제출 시점을 기록한다. 방문 이력과 판매처 존재 확인 상태를 분리한다. |
| 후기 | 판매처, 작성자, 별점, 본문, 작성·수정·공개 상태를 연결한다. 공개 여부와 집계 대상을 일치시킨다. |
| 신고·운영 기록 | 대상 ID, 이유, 검토 상태·결정과 병합 대표 ID를 연결한다. 처리 후 원래 이력과 근거를 찾을 수 있어야 한다. |

보존 기간, 삭제 요청 처리, 운영 기록 접근 범위, 데이터 복구 기준은 DEC-007에서 확정한다. 출시 초기 데이터와 시스템 테스트 데이터를 구별한다.
